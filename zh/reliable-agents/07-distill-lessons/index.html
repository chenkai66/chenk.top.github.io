让 Agent 靠谱起来（7）：把每一道疤都变成一条规则

让前面所有纪律产生复利的最后一条纪律：每次修完，把教训蒸馏成系统自己能消费的形态（一个测试、一条扫描规则、一个安全模式），让这道疤变成防止下一次发生的自动化，而不是一份要用惨痛方式重学的口耳相传。

这个系列里的每个教训都以同样的方式开场：某个东西坏了、我诊断了它、我修了它。这是正常的循环，大多数人到此为止。这最后一篇讲修完之后那一步，那一步把一道私人的疤变成系统的一个永久属性，好让没有人（包括未来的你）为它流两次血。

我把它想成反过来的师傅带徒弟。师傅教徒弟的，不只是做什么，还有怎么判断什么时候做。你修好一个东西时，你刚学会了一个判断。问题是：你能不能把这个判断教给系统，让系统下次不用你就做出对的决定？

一个只活在你脑子里的教训，浪费在哪#

一个没被蒸馏的修复，以一种可预测的方式衰减。你修好一个微妙的 bug，比如一个必须在调用之前重置、而不是之后重置的计数器。你在那一刻深刻地理解了它。六周后，在另一个模块里，你（或一个 agent、或一个同事）又写了一遍那个调用之后才重置，因为那份理解活在你脑子里，而你的脑子已经往前走了。

知识存在过。它只是不在下一个错误会发生的地方。这就是核心的浪费：存在对话上下文里、或某个人记忆里的教训，在下一次发生的地点和时刻并不在场。它们跟不存在也差不多。

所以纪律是：修完一个东西之后，问自己"什么东西本来能自动抓住它，我能不能把它加上"。 不是"我改了什么"，那只是 diff。有价值的产物，是那条本来能防住这一类 bug 的规则，放在它下次会触发的地方。

蒸馏决策逻辑，不是 diff#

这里是大家做错的地方：他们记的是改了什么，而不是怎么决定。“把第 42 行改成调用前重置"是个 diff，它对这个 bug 有帮助，对别的都没有。系统真正能从中学到的，是决策逻辑：“必须在一次操作开头保持干净的状态，应该在那次操作的开头初始化，而不是在上一次操作的结尾，因为’成功时清理’一旦成功没发生就会泄漏。”

第二种形态能泛化。它能变成一条 code-review 清单项、一条标记"调用后重置"模式的 lint 规则、一条 agent 在任何地方碰计数逻辑之前会读的笔记。Diff 干不了这里任何一件事，它太具体了。当你蒸馏一个教训，去捕捉模式 → 诊断 → 修复这个三元组，尤其是那个为什么和那个怎么判断边界情况，因为正是这个，让规则能应用到你还没见过的情形上。

这也是为什么整个系列里，我把每个教训都说成一条带着理由的原则，而不是一个配方。“先扣费再产出，因为产出和扣费之间崩溃是无声的利润损失。“那个理由，正是让规则能移植到一个配方并不字面适用的新情形上的东西。

把教训喂给那个自动执行的东西#

这份纪律的最高形态，是把教训交给一个不用你就据此行动的组件。看你的系统是什么，那是一个不同的产物：

  • 如果你有测试套件： 修好一个 bug 的那一刻，加一个把它的签名编码进去的回归测试，一个触发这一类 bug 的输入，断言正确的行为。现在这个教训在每次改动上都跑、永远、无人值守。bug 可以回来，但它没法悄悄地回来。
  • 如果你有任何静态分析或扫描： 把模式变成一条规则。一条针对"调用后重置"形状的 lint 规则。一个扫描"碰了可补偿数据、却没过滤标记的读路径"的扫描。规则会在下一个实例发布之前就找到它。
  • 如果你有一个自主改进组件（某个主动扫描问题、并提议或应用修复的东西）：用它消费的形态把模式教给它，一个 backlog 条目、一个扫描签名、一个安全变换。然后验证它真的能自己拾起并应用这个模式。（而且照第四篇：确认它在真实路径上跑了，不只是你加了它。）
  • 如果这些你一个都没有： 至少，把教训写在下一个做这活儿的人真的会看到的地方，一份和代码放在一起的文档，不是一条会滚走的聊天消息。标准是"在下一个错误的地点在场”，一份代码旁边可搜索的笔记达标；一次对话不达标。

贯穿始终的那条线：把教训尽你所能地挪到靠近自动执行的地方。 一个每次提交都跑的测试，胜过一个人类可能跳过的清单项，胜过一份有人可能读的笔记，胜过一个已经在遗忘的脑子里的知识。

复利#

这就是为什么这最后一条纪律，是让另外六条值点钱的那一条。前面每一篇都是一个我付过一次费的教训。孤立地看，每一个正好值一个被避开的 bug。但蒸馏进系统（作为测试、作为扫描规则、作为一个 agent 会查阅的原则），每个教训就不再是一次性的挽救，而变成一条系统跌不破的永久地板。

这就是"随时间变得更可靠的系统"和"只是让同样的故障穿上新外套反复累积的系统"之间的区别。一份没被捕捉的可靠性纪律，会退化成民间传说。捕捉下来，它就产生复利：第 30 轮真的比第 3 轮更安全，不是因为人变聪明了，而是因为三十道疤变成了三十条系统现在自己执行的规则。

把门建起来。给靠不住的观察者织网。先扣费再产出。验证它跑了，不是它部署了。让自主走在记录的身份上。重新验证旧的修复。然后，那一步让这一切经久的，把这里每一个辛苦得来的判断，变成系统不用你就执行的东西。

从这里往哪走#

这个系列里没有单独的一招，这正是重点。可靠的 agent 系统，来自一摞关于什么才算完成的小纪律，也来自那条元纪律：把每个教训变成自动化，好让这一摞不停地长。挑一个你在自己系统里最眼熟的故障模式，加上那一个本来能抓住它的守卫，把它编码好、让它没法悄悄回来。然后下次坏点什么的时候，再做一遍。这个循环，耐心地跑下去，就是全部的方法。
