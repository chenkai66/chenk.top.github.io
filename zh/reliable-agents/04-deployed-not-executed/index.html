让 Agent 靠谱起来（4）：部署了，不等于跑起来了

发布软件时最诱人的一个谎：我部署了，所以它能用。代码可以发出去、杵在那儿，从来没在你以为它跑的那条路上跑过。两种故障模式：造好了没接线、部署了没执行，以及怎么证明功能真的触发了。

有一种特定味道的自欺，会在你的改动大到有了管线之后冒出来。你写了个功能。你部署了它。部署成功。你标记完成。然后它从没跑过，不是因为它坏了，而是因为在你在乎的那条路上，根本没有东西真正调用它。

这个 bug 我发得够多，多到现在我把"部署了"和"能用"当成两个不相关的事实，直到被证明相反。这一篇讲这道缝以哪两种方式裂开，以及各怎么补。

故障模式一：造好了，没接线#

后端支持这个功能。函数存在，正确，甚至测过。但那个本该用它的东西没用：调用方把旧值写死了、或者读了一个新代码从不填充的字段、或者 UI 的下拉框里缺了那个新选项。

我碰过最锋利的一次：一条数据管线升级后要算出几个新字段。计算是对的。但组装最终结果对象的那一步，做的是显式的逐字段映射，没人把新字段加进那个映射。于是管线尽职地算出它们，然后在最后一步悄悄把它们扔在地上。每一个单独的零件都对。功能之所以隐形，是因为有一个胶水层从没得知它的存在。

这个特别值得抓，因为修法通常极小（往映射里加三行），而收益很大（一个原本啥也没干的完整功能现在能用了）。但你只有把那个值端到端追一遍才找得到：从它被产出的地方，追到它真正被消费、被展示的地方。“函数返回了对的东西"不够；你得跟着这东西一路跟到界面。

习惯是：当你加一个能力，把它追到使用点，不只是产出点。 问一句"谁读它，我是不是更新了每一个读它的地方”，和上一篇补偿标记规则里那种整体纪律是同一回事。后端支持它，加上 UI 写死它，等于一个没人够得着的功能。

故障模式二：部署了，没执行#

接线没问题。代码发出去了。但它还是没跑，因为你以为会触发它的那条路，不是生产实际走的那条。

配置开关默认关。新分支藏在一个真实环境里永远不为真的条件后面。定时任务注册了，但调度器只在进程空闲时才触发，而你的进程从不空闲。handler 装上了，但触发它的事件在上游就被过滤掉了。每种情况都是：存在、正确、部署了，然后冰凉。零次执行。

唯一的解药是观察代码在真实路径上真的跑起来。不是"它部署了"。不是"测试过了"。是一行日志、一次指标自增、一个你能看见的副作用，由生产触发器干生产的事产生。如果你指不出证据证明这条代码路径在真实环境里触发过，那你没验证它，你只验证了它存在。

对任何我真在乎的东西，我都加一个便宜的、能 grep 的信号：新路径第一次执行时打一行日志，然后我去让真实触发器发生，确认那行出现了。这感觉很冗余，一直到有一天它揭示出：你精心发布的功能，自上线以来恰好跑过零次。

验证已生效，又不骗自己#

一个具体又常见的实例：你把一个改动推过一条构建-部署管线，管线后面坐着缓存或 CDN，你想确认新版本真的上线了，而不是一份过期的缓存副本。

天真的检查（“页面里有我的新文字吗”）很脆。缓存会端过期副本，更糟的是，如果你的构建会 minify 输出，它可能把你正在 grep 的那个字符串给剥掉（注释消失、空白塌缩、标识符被改名）。你 grep 一个被优化没了的东西，然后错误地断定部署失败了。

两个真正管用的办法：

  • Grep 一个能扛过优化的字符串字面量，不是注释、不是变量名。Minifier 会保留面向用户的字符串和某些字面量；它删注释、给局部变量改名。据此挑你的针。
  • 更好的：比内容哈希。 如果你的构建工具按内容给输出文件名做指纹（现代 asset 管线里很常见），那线上那个文件名就是内容的哈希。拉一下线上页面，读它引用的是哪个 asset 文件名，把那个哈希和你本地构建产出的比一比。匹配，就说明线上正在提供的正是你的字节。这招对缓存撒谎和 minification 免疫，它比的是身份，不是在搜子串。

再说一遍通用原则：以一种中间层无法伪造的形态，去验证你在乎的那个结果。 “文字在那儿"能被过期缓存伪造。“内容哈希匹配"不能。

为什么这事儿总在发生#

部署了没执行之所以是个如此顽固的陷阱，是因为每一个中间成功都是真的。构建确实成功了。部署确实完成了。函数确实正确。每一盏绿灯都在诚实地讲述它自己那个狭窄范围里的事实。没有任何单独一盏绿灯断言的，是你真正在乎的那个端到端命题：这个能力改变了一个真实用户在真实路径上体验到的东西。

这和第一篇（每块都绿、整体是坏的）、第二篇（代理指标 vs 真实结果）是同一种病，只是从发布这一端看过去。解药永远是同一个形状：拒绝把一串局部成功当作全局结果的证明。把东西追到它被使用的地方。看它在真实路径上触发。比身份，不比代理。

接下来的内容#

下一篇讲怎么让 agent 自己动手（自主清理、自愈、自动修复），又不让它把不该删的东西给端了。这个张力是真实的：自主本身就是全部意义，但一个 agent 基于一个坏推断自信地删东西，比完全不自动化还糟。解法是信任但验证，以及只按精确记录的身份去删。
