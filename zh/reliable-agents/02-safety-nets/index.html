让 Agent 靠谱起来（2）：兜底网胜过靠不住的观察者

概率型的触发器（IntersectionObserver、LLM 判断、事件监听）会悄无声息地失败，留给你的是看不见的内容和卡死的状态。修法是给每个不可靠的观察者垫一层确定性兜底，外加一条硬规则：渲染出来的结果才是真值，不是观察者的意见。

第一篇讲的是构建才是唯一的验收门。这一篇讲的是当观察者本身不可靠时会发生什么。所谓观察者，就是那个本该告诉你"这块活儿落地了"的东西。因为有时候代码是对的，而那个本该激活它的触发器，就是……没触发。

我在这一类 bug 上栽掉的时间多得让人难堪，所以这一篇基本上是道疤。

看不见的内容#

我有个页面，内容随滚动渐显：每张卡片一开始藏着，进入视口时淡入。机制是一个 IntersectionObserver，盯着每张卡片，越过可视线时给它加上"可见"状态。干净、标准，demo 里跑得好好的。

上了生产，最上面两到四张卡片停在 opacity: 0。看不见。本该有内容的地方是一片空洞。

最让我抓狂的是这一点：我去查 DOM，一切都正常。 卡片数量对，没有布局空隙，标记也没错。我跑的每一个针对结构的自动检查都说"页面健康，卡片齐全"。而一个真人看着实际渲染出来的页面，看到的是个窟窿。

那个观察者，对于加载时就已经靠近视口顶部的卡片，悄悄地没触发（这是那个 API 一个已知的坑）。卡片存在，只是永久透明。而任何 DOM 层面的断言都抓不到"存在但不可见"，因为存在和可见是两个不同的属性，而那个便宜的检查只看了第一个。

第一课：渲染出来的结果才是真值#

DOM 说一套。截图说另一套。截图是对的。

这远不止适用于网页。每当你验证一个概率型或事件驱动的系统，都会有一股诱惑，去查那个好查的代理指标（DOM 节点数、那个"任务已标记完成"的标志位、那行说"handler 已注册"的日志），而不是你真正在乎的实际结果。代理指标更便宜，而且通常和成功相关。直到它不相关的那一次，它就会满怀自信地对你撒谎。

我现在守的规则是：验证你真正在乎的那个东西，而且要以用户体验到的形态去验证。 视觉改动，就意味着截图，不是 DOM 查询。“数据写进去了"这个断言，就意味着把那行读回来，而不是信任写调用的返回值。“agent 完成了任务”，就意味着去检查它本该产出的那个 artifact，而不是它给自己设的那个状态字段。

还有一个更锋利的版本，是我在同一个 bug 上硬学会的：别在过渡进行中测量。 我第一次"验证修复"时，在淡入动画还在跑的时候去查 opacity，拿到一堆垃圾读数，每次重跑都不一样。真值是沉降后的状态。等过了动画、等过了错峰延迟、等过了所有安全计时器，再来判断你看到的是什么。

第二课：给每个概率触发器垫一层确定性兜底#

修好验证，只是让你知道什么时候坏了。它挡不住你去坏。要挡住，模式是在靠不住的触发器底下垫一层确定性兜底。

那个观察者是一种优化：它在最完美的时机、惰性地、高效地把东西显示出来。但它的职责（“确保每张卡片最终都变可见”）有一个笨得多、也可靠得多的实现。所以我现在两个一起跑：

2
3

1. IntersectionObserver（又快又准那条路）  —— 卡片进入视口时逐张触发
2. 滚动事件监听                            —— 任何滚动都重新检查一遍
3. 一次性安全计时器（加载后约 1.2s）        —— 强制显示任何仍藏着的东西

第 2、3 层就是兜底网。观察者漏了某张卡片，用户一动，滚动监听立刻补上。如果用户根本不滚（最上面那几张卡片，恰好就是出问题那种情况），计时器过一拍之后扫进来，把所有仍卡住的强制显示。精确那条路高效地处理常见情况；两条笨路保证那个不变式：一切都变可见，不管观察者干了什么。

有两个实现细节很关键：

  • 让显示操作幂等。 三层都可能去显示同一个元素。这个操作必须能安全地跑两遍（设为可见，而不是切换），否则几层会互相打架。
  • 先把观察者自己的边距放宽。 加兜底网之前，我把观察者的 root margin 设得很宽（元素真正上屏之前很早就触发）、threshold 设为零（第一个像素就触发）。光这一下就修掉了大部分漏触发；兜底网是为剩下那些准备的。

这个模式在浏览器之外的地方#

这不是个前端小技巧。凡是有一个概率型或尽力而为的机制，去把守一件必须发生的事，这个形状就会出现：

  • 一个 LLM 在判断任务是否完成。 有用，但有时会错。给它底下垫一个确定性后置检查：那个必需的产出，是不是真的存在、能不能解析？
  • 一个本该推进工作流的事件或 webhook。 事件会丢。加一个周期性扫描，找出任何卡在中间态、超时的东西，把它往前推。
  • 一个本该已经拿到你新内容的缓存或 CDN。 别信"我部署了”。去拉线上那份 asset，把它的内容哈希和你构建出来的比一比。（内容指纹化的文件名让这事儿变得极简单：线上那个文件名字面上就是哈希。）

统一的原则是：任何把守不变式的概率型机制，都需要一个确定性的后盾，而且这个后盾要直接断言那个不变式（“东西可见了"“那行存在"“工作流推进了”），而不是那个好轮询的代理指标。

老实说，代价是什么#

兜底网不是免费的。你在跑冗余的活儿：一个大部分时候找不到事做的滚动 handler、一个通常什么都没扫到的扫描、一个通常都匹配的哈希比对。这正是重点。冗余廉价且恒定；它挡掉的那个故障稀有且灾难性（生产上看不见的内容，而你的自动检查还发誓一切正常）。这笔交易我每次都做。

有一点要盯着：别让兜底网把一条坏掉的精确路径糊过去。如果你的安全计时器在干所有的活儿，因为观察者根本从不触发，那你加的不是韧性，你只是换到了一个更慢更笨的机制、还把这个退化藏了起来。兜底网抓到东西时打个日志。如果它在不停地抓，说明快路径坏了，而兜底网在替它遮丑。

接下来的内容#

下一篇从"它发生了吗"走到"它是不是恰好发生一次、而且顺序对"。当一个 agent 步骤要花钱、或者要改共享状态时，你写入的顺序，决定了半路崩溃是丢钱、重复扣费、还是保持干净。模式是先扣费再产出，核心就是在正确的顺序上保持偏执。
