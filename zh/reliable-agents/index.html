让 Agent 靠谱起来

May 14, 2026 让 Agent 靠谱起来 10 分钟

让 Agent 靠谱起来（7）：把每一道疤都变成一条规则

让前面所有纪律产生复利的最后一条纪律：每次修完，把教训蒸馏成系统自己能消费的形态（一个测试、一条扫描规则、一个安全模式），让这道疤变成防止下一次发生的自动化，而不是一份要用惨痛方式重学的口耳相传。

May 12, 2026 让 Agent 靠谱起来 8 分钟

让 Agent 靠谱起来（6）：每一轮都重新验证旧的修复

在一个长期运行的优化循环里，最危险的退化，是那个悄悄把你早就修好的东西又弄坏了的退化。防住它的习惯：每一轮，都在真实触发路径上重新验证之前的修复，不只是那个新改动。

May 10, 2026 让 Agent 靠谱起来 10 分钟

让 Agent 靠谱起来（5）：让自主不会删错东西

自主清理和自愈，正是 agent 的全部意义，也是删错数据最快的路。解法：只对精确记录的身份动手、任何破坏性步骤之前拿计数和现实核对、信任一个信号之前先审问它。

May 8, 2026 让 Agent 靠谱起来 8 分钟

让 Agent 靠谱起来（4）：部署了，不等于跑起来了

发布软件时最诱人的一个谎：我部署了，所以它能用。代码可以发出去、杵在那儿，从来没在你以为它跑的那条路上跑过。两种故障模式：造好了没接线、部署了没执行，以及怎么证明功能真的触发了。

May 6, 2026 让 Agent 靠谱起来 10 分钟

让 Agent 靠谱起来（3）：先扣费，再产出

当一个 agent 步骤要花钱、或者要改共享状态，你写入的顺序比那一步本身更重要。先扣费再产出、调用前先重置计数器，让每一次改动都能扛住最糟时刻的崩溃。

May 4, 2026 让 Agent 靠谱起来 10 分钟

让 Agent 靠谱起来（2）：兜底网胜过靠不住的观察者

概率型的触发器（IntersectionObserver、LLM 判断、事件监听）会悄无声息地失败，留给你的是看不见的内容和卡死的状态。修法是给每个不可靠的观察者垫一层确定性兜底，外加一条硬规则：渲染出来的结果才是真值，不是观察者的意见。

May 2, 2026 让 Agent 靠谱起来 10 分钟

让 Agent 靠谱起来（1）：构建，才是唯一的验收门

三个 agent 各改一个 TypeScript 仓库的一块，各自跑 tsc 都通过，各自报成功。合并后的代码八秒就编译失败。修法只有一条规则：只有母 agent 的整体构建才算完成。
